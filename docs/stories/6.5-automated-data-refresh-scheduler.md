## User Story

As a system, I want to automatically refresh external data sources on a schedule, so that forecasting models use the most current macro-economic data without manual intervention.

---

## Acceptance Criteria

### AC1: APScheduler Integration ✅

- Install `APScheduler>=3.10`
- Configure `AsyncIOScheduler` for async job execution (integrates with MCP server event loop)
- Store job state in PostgreSQL using `APScheduler.jobstores.sqlalchemy` (persistent across restarts)
- Use UTC timezone for all scheduled jobs
- Implement graceful shutdown on application exit (`scheduler.shutdown()` in cleanup handler)

### AC2: Refresh Schedule Configuration ✅

- **Daily (06:00 UTC):** Weather (IPMA), Electricity Prices (OMIE), CO₂ EUA
- **Weekly (Sunday 06:00 UTC):** Building Permits (INE), Mortgage Loans (BPstat), Diesel Prices
- **Monthly (1st day, 06:00 UTC):** Construction Output, Cost Index (INE), Cement Consumption (ATIC)
- Configuration via environment variables using cron syntax:
  - `REFRESH_CRON_DAILY=0 6 * * *` (daily at 06:00 UTC)
  - `REFRESH_CRON_WEEKLY=0 6 * * 0` (Sunday at 06:00 UTC)
  - `REFRESH_CRON_MONTHLY=0 6 1 * *` (1st of month at 06:00 UTC)

### AC3: Error Notifications ✅

- Log failed refresh attempts via structured logging (ERROR level)
- Retry failed jobs: 3 attempts with exponential backoff (1s, 2s, 4s) per Story 6.1 pattern
- Log retry attempts with attempt count and delay (WARNING level)
- Optional: Email/Slack notifications (future enhancement, not MVP)

### AC4: Manual Trigger Endpoint (MCP Tool) ✅

```python
@mcp.tool()
async def refresh_external_data(source_name: str | None = None) -> str:
    """
    Manually trigger external data refresh.

    Args:
        source_name: Specific source to refresh (None = all sources)

    Returns:
        JSON with refresh status for each source (success/failure, duration, records updated)
    """
```

### AC5: Data Staleness Detection ✅

- Alert if external data >30 days old (WARNING level log)
- Mark source as stale in `external_data_sources.last_refresh_at`
- Forecasting continues with stale data (degraded mode)

### AC6: Unit Tests (80%+ coverage) ✅

- Scheduler configuration and job execution
- Error handling and retry logic
- Manual trigger via MCP tool

### AC7: Integration Tests ✅

- Scheduled refresh executes successfully
- Staleness detection triggers warnings
- Manual refresh via MCP tool

## Technical Notes

- **APScheduler:** Lightweight Python scheduler, no external dependencies (vs Celery which needs Redis/RabbitMQ)
- **Job Persistence:** Use `APScheduler.jobstores.sqlalchemy.SQLAlchemyJobStore` with existing PostgreSQL connection
- **Timezone:** All scheduled jobs MUST run in UTC to avoid DST issues
- **Graceful Shutdown:** Register `atexit` handler or use MCP server lifecycle hooks for `scheduler.shutdown()`
- **Async Pattern:** Use `AsyncIOScheduler` with `asyncio.create_task()` for non-blocking job execution
- **Job Coalescing:** Enable `coalesce=True` to prevent job backlog after downtime
- **Misfire Grace Time:** Set `misfire_grace_time=3600` (1 hour) to handle brief outages
