### Lessons Learned

1. **Data-First, Not Requirements-First**
   - Ground truth must be created from **actual database inspection**, not requirements documents
   - Assumption: Data matches requirements → Reality: 12% → 77.6% after alignment
   - Prevention: Data dictionary BEFORE test creation

2. **Validate Basics Before Building Advanced Features**
   - Over-engineering (element-aware chunking, complex SQL) before validating test data alignment
   - Simple period mapping (Q3 → Aug-25) unlocked major accuracy gains
   - Prevention: "Does this data exist?" check before feature implementation

3. **Code Quality Debt Accumulates Fast**
   - Files exceeding 1000-1500 lines become maintenance nightmares
   - Epic 3 (agentic orchestration) will be harder if we don't refactor now
   - Prevention: Hard 1000-line limit, refactor before next epic

4. **User Testing Reveals What Automated Testing Misses**
   - 100% pytest pass rate but Project Lead can't use MCP tool (no config documentation)
   - Usability gaps invisible to automated validation
   - Prevention: UAT after every epic before marking "complete"

5. **Strategic Pivots Are Healthy (When Data-Driven)**
   - 2 major pivots in Epic 2 (element-aware → SQL, SQL backend → ground truth normalization)
   - Each pivot based on measured accuracy, not opinions
   - Final result: 77.6% (exceeded 70% target)

6. **Epic Overlap Planning Still Missing**
   - Epic 1 action item not addressed: Start Epic 3 during final Epic 2 stories
   - Result: 2-week prep sprint needed before Epic 3
   - Prevention: Architecture design for Epic N+1 during final stories of Epic N

7. **Documentation Gaps Block User Adoption**
   - MCP server working since Epic 1 but no setup guide for users
   - Project Lead couldn't connect to own system
   - Prevention: User-facing documentation as acceptance criteria

8. **Excerpt Validation Methodology Works**
   - Story 2.14: 100% on excerpt (12/12) proved implementation correct
   - Generic validation (12% on 50/50) revealed test data misalignment
   - Prevention: Always validate on excerpt first before full test suite

9. **Period Normalization Is Reusable Infrastructure**
   - Story 2.15's 150-line module handles Q1-Q4, H1-H2, FY, month-year mappings
   - Production-ready for Epic 3-5 queries (no additional work needed)
   - Pattern: Build reusable utilities, not one-off fixes

10. **Fuzzy Matching Handles Real-World Variations**
    - PostgreSQL pg_trgm extension: 80% entity accuracy with zero new dependencies
    - Handles "Group" → "Currency (1000 EUR)" variations
    - Pattern: Leverage database features before adding external libraries
